# Agent Workbench 本轮目标验收审计

日期：2026-07-16

## 1. 最终结论

- 本轮约定的项目验收目标已完成：真实模型边界、单轮与多轮对话、Memory、Context、Skill 路由、Tool/Gate、Trace、Artifact、新闻来源约束、政策证据边界和前端响应式布局均已实际运行验证。
- 真实模型固定为 `deepseek-v4-flash`。没有可用鉴权、模型名不匹配或请求了不存在的模型时，后端明确拒绝执行，不再使用本地假模型生成貌似成功的答案。
- 最终业务语义矩阵 `17/17` 通过；完整测试 `151 passed`；Harness linter、Python 编译检查和 JavaScript 语法检查通过。
- 当前结论是“满足单用户 Agent Harness 学习、作品集展示和面试讲解要求”，不是“已经等同于大厂完整生产系统”。

## 2. 本轮具体完成内容

1. 删除伪模型和不可用模型入口，只保留实际配置并可调用的 `deepseek-v4-flash`。
2. 将模型选择放入 Composer；模型不可用时前后端都明确阻断执行。
3. 修复聊天记录与控制台重叠，聊天记录成为独立可滚动区域；侧边栏支持收起和移动端抽屉。
4. Skills 改为 `/auto`、`/chat`、`/policy`、`/news`、`/research`、`/wiki` 斜杠命令，不再用大卡片占据聊天区域。
5. 将本轮执行过程放到回答上方，支持查看每一步的上下文、输出、工具、Gate 和原始 Trace。
6. 修复通用问答被错误路由到政策或 Wiki 工作流的问题；斜杠命令可以覆盖会话默认路由。
7. 为企业事实回答绑定实际使用的 `fact_id`；没有证据时不附无关引用，也不补写未知事实。
8. 为政策分析建立“直接适用、条件适用、明确不适用、证据不足”四分类，并区分强制义务与政策相关性。
9. 将用户保存的报告顺序偏好写入长期 Memory；后续会话读取后真正改变政策报告排序。
10. 多轮政策追问显式记录 `history_read`，可在 Trace 中核对继承了哪些历史问题。
11. 新闻查询编译日期、完整时间、时区、数量、来源类型和发布主体约束；不足时少给并披露缺口，不用未请求来源补足数量。
12. 新闻摘要改为完整的事件级事实，并生成与具体变更对应的影响链和可验证指标。
13. 为上线评审类问题输出产品、研发、合规三方的负责人、验收证据、阻断条件和量化阈值。
14. 对确定性法条核验如实标记为 deterministic，不伪造模型调用事件。
15. 形成可重复运行的业务验收、真实模型性能基准、桌面/移动 UI 检查和独立审查流程。

## 4. 真实 Flash 性能结果

同一政策四分类问题连续运行 3 次，取中位数：

| 指标 | 已记录初始方案 | 当前方案 | 变化 |
|---|---:|---:|---:|
| 端到端耗时 | 17,934.92 ms | 11,222.24 ms | 降低 37.43% |
| 适用性分析输入 | 8,647 tokens | 3,070 tokens | 降低 64.50% |
| 适用性分析耗时 | 13,021.08 ms | 5,888.47 ms | 降低 54.78% |

三次运行均满足四分类正确、强行关联数为 0、无未支持结论、上下文受预算约束、Trace 中存在两个 Subagent 调用等验收条件。该对比是同项目已记录初始 Run 与当前三轮中位数的工程基准，不宣称跨模型或跨硬件的通用性能结论。

## 5. 前端设计参考与验收

前端没有复制其他项目源码，而是参考成熟产品的交互模式后用本项目原生 HTML/CSS/JavaScript 实现：

- ChatGPT 类产品：会话侧边栏、Composer 内模型状态、移动端抽屉。
- Claude/Codex 类 Harness：把运行过程与本轮回答放在同一信息流中，而不是常驻右侧大面板。
- 命令面板类产品：使用 `/` 发现和选择 Skill。
- Langfuse 类可观测产品：采用 Run -> Step -> Tool/Gate/Artifact 层级，但只展示本轮相关证据。

公开参考资料：

- [ChatGPT Release Notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)：Composer 内模型选择、会话侧边栏和移动端布局。
- [Claude Code CLI Reference](https://docs.anthropic.com/en/docs/claude-code/cli-usage)：交互会话与 Slash commands。
- [Langfuse Observability](https://langfuse.com/docs/observability/overview)：Trace、Observation、模型调用、工具与检索步骤的结构化观测。
- [Vercel AI SDK Guide](https://vercel.com/academy/ai-sdk)：对话消息、流式响应、工具调用和生成式 UI 的产品结构。

最终桌面端与 `390 x 844` 移动端各通过 20 项动态检查：无整页空白滚动、无横向溢出、聊天记录可滚动、控制台不重叠、Trace 不被 Composer 遮挡、中文无乱码、上下文与观测摘要可见。

浏览器最终实测保留了普通会话“来源边界演示”：`session_id=3329da012c44476abc84d42ba5c8a3c9`，`run_id=1a9ed6f6415449bc84d157b18169b85d`。页面展开后可见 7 个步骤、3 次工具、1 个 `ask` 门控、3 个产物、上下文预算和“确定性执行（0 次模型调用）”。修复前的旧会话保持原始结果，作为可回放历史 Run，不篡改旧答案。

## 6. 仍然存在的明确边界

- 当前是单用户 Workbench，不包含多租户隔离、配额、审计租户和组织权限模型。
- 外部连接器是有限集合；Google DeepMind 官方源当前未接入，系统会披露而不会伪造或换源补齐。
- 政策模块用于证据检索、适用性分流和决策辅助，不等同于完整法律意见。
- 当前没有宣称大规模并发、跨区域容灾、完整 SRE 指标或企业统一身份认证已经完成。
- 前端已达到成熟工程 Demo 和作品集展示要求，但不能仅凭本次验收宣称达到某一家大厂完整设计系统的像素级水准。

## 7. 独立审查

独立审查第一次给出 No-Go，并发现自动化验收遗漏了两个真实问题：

1. UTC 时间戳被截成日期，导致北京时间窗口外的事件错误通过。
2. 官方 GitHub Release 被错误当成用户限定的“发布方自有官网或官方研究博客”。

修复代码和验收标准后，独立审查复核结果为 `Go`，定向范围内无残留 P0/P1/P2。六维评分为：需求覆盖 10、证据准确 10、企业特异性 10、行动性 9.5、不确定性表达 10、上下文连续性 10。该评分是本轮 17 个验收场景的代码与运行证据审查，不代表完整商业产品评分。
