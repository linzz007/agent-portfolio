# myAgent 与 MACT 随机盲测报告

日期：2026-06-23

## 结论

旧的 18 条/数据集结果不能作为独立测试成绩。那些样本曾被用于错误分析、提示词
修改和规则选择，因此应重新定义为开发集。

本次从三个完整数据集中重新抽取 12 条/数据集，共 36 条。抽样时排除了现有
`datasets_ready` 和 `outputs` 中出现过的全部样本 ID 和表格 ID。抽样完成后先冻结
输入、随机种子和 SHA-256，再运行 myAgent 与 MACT；六个任务全部结束前没有修改
代码、提示词或样本。

盲测中，myAgent 为 21/36（58.3%），MACT 为 24/36（66.7%）。myAgent 的平均
真实 API token 为 2,763/题，MACT 为 9,073/题，myAgent 节省 69.5%。

当前证据支持“myAgent 更省 token”，但不支持“myAgent 准确率稳定超过 MACT”。

## 冻结协议

- 基础随机种子：`1235722681`
- 每个数据集：12 条，共 36 条
- 历史排除：90 个样本 ID、81 个表格 ID
- WTQ：12 张不同表格
- TabFact：6 true、6 false，12 张不同表格
- CRT：4 Yes/No、4 其他闭集、4 开放题，12 张不同表格
- 模型：`deepseek-v4-flash`
- Temperature：0
- Thinking：disabled
- myAgent：默认关闭多视角验证
- MACT：单候选，最多 3 个 ReAct 步骤
- 统一评测器：`code/evaluate_results.py`

冻结文件和哈希见：
`datasets_ready/blind_holdout_2026-06-23/manifest.json`。

样本量较小，区间高度重叠，因此不能用这次结果断言 MACT 的准确率显著更高。

## 过拟合判断

代码中没有按旧样本 ID 或 gold answer 直接写死答案，但旧样本被用于反复诊断和
规则设计，例如答案标签推断、特定语言歧义、计数约束和舍入策略。这属于开发集
上的提示词/规则选择过拟合，而不是答案泄漏式过拟合。

因此：

1. 旧 benchmark18 必须标记为开发集结果。
2. 本次 36 条在完成错误分析后也不能再作为最终测试集，应标记为第二开发集。
3. 专利和论文的最终数字必须来自下一批从未查看、从未调参的冻结测试集。

## myAgent 盲测错误类型

### WTQ

- 4 条生成代码执行失败：列语义选错、使用未开放的 `re`、文本匹配失败、未处理
  `TBA` 等异常值。
- 多答案问题被推断为标量，返回逗号拼接文本，不满足 WTQ 集合答案协议。
- “非完赛”“日期之后”等题出现条件覆盖不完整。
- 一条相对当前年份的问题使用动态年份，但数据集 gold 来自旧年份，存在时效歧义。

### TabFact

- 一条低风险分类题判断错误。
- 一条代码使用未加入安全白名单的 `isinstance`，执行失败。

### CRT-QA

- `home or away` 被错误推断为 Yes/No，说明隐式答案模式规则过宽。
- 比较题混淆“总数”“平均每组”和“相对其他类别”的比较单位。
- NHL rights、decision/finish 等领域语义没有被表头和数据充分约束。
- 平均值契约固定保留两位，但部分 gold 要求整数舍入。
- 双数值答案缺少结构化 tuple/list 契约。

## 当前 myAgent 架构

1. **模型后端层**：通过参数选择 DeepSeek、OpenAI-compatible、Azure 或本地模型，
   API key 仅从环境变量读取。
2. **数据适配层**：将 WTQ、TabFact、CRT 统一为 `question + table_text + answer +
   metadata` 的 JSONL 协议。
3. **会话状态层**：`TQASessionState` 保存路由、压缩、答案契约、代码、执行结果、
   critic 反馈、token 和延迟。
4. **Router**：结合语义复杂度和预计涉及单元格数量选择 SIMPLE/COMPLEX。
5. **TableCompressor**：按问题保留相关行列；聚合题保留全行，跨列全局比较保留
   全部候选列。
6. **AnswerContract**：在不读取 gold 的前提下推断标量、列表或闭集标签，并负责
   格式归一化、标签合法性和平均值精度。
7. **复杂推理链**：Planner 生成计划和 pandas 代码，Calculator 在受限命名空间
   执行，Critic 检查证据、逻辑和答案契约，失败时最多重规划 3 次。
8. **静态校验**：在执行前用 AST 阻止 `X of N` 错误去重、同组计数未排除参照项
   等已知 grounding 错误。
9. **输出与评测**：保存真实 API usage、压缩比例、执行错误和结构化答案；统一
   评测器分别执行 WTQ denotation、TabFact 二分类和 CRT 规范化匹配。

## 相较初始版本的变化

- 从单一/固定模型调用改为可参数切换的模型后端。
- 从零散数据读取改为三数据集统一适配器。
- 从仅靠 Router 和自然语言最终回答，改为类型化答案契约与结构化结果优先。
- 从固定短表预览改为问题感知压缩，并为聚合、相对行、跨列比较保留必要证据。
- 从模型代码直接执行改为受限执行、静态 AST 校验和契约失败重规划。
- 增加表主题元数据、真实 token、延迟、执行失败和统一正确率评测。
- 多视角验证保留为可选消融，不在默认主路径开启。

## 专利与论文建议

可以把专利重点放在可验证的系统机制：答案契约、选择性推理、证据保留压缩、
grounding 校验、受限执行和成本观测。不要把旧的 98.1% 作为最终效果结论。

下一轮正式验证建议：

1. 完成本轮错误修复后冻结代码和 prompt。
2. 预注册随机种子、排除列表、样本量、模型参数和评测器哈希。
3. 每个数据集至少抽取 100 条未见样本，并保持 TabFact/CRT 分层。
4. myAgent 与 MACT 使用完全相同的样本、模型和 API 参数。
5. 报告 Accuracy、95% 置信区间、配对显著性、token/题、执行失败率和延迟。
6. 对 AnswerContract、Compressor、AST Validator、Critic 分别做消融实验。
7. 最终测试集一旦解封，只允许报告结果，不允许继续修改后重算同一测试集。
