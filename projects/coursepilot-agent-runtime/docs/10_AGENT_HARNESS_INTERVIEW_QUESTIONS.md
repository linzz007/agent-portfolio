# AI Agent 面试题库（简历项目版）

> 这份题库按你当前简历来设计：面试官已经看到的是“RAG + Memory + MCP 多智能体课程学习系统”和“已上线 Dify 高校就业辅导 Agent”，而不是“Agent Harness”。所以训练时不要主动把项目包装成 Harness；只有当被追问生产化、治理、评测、运行时边界时，再用“运行时治理层 / 工程闭环”去解释。

## 使用方式

每轮训练采用：

1. 面试官只问一个问题。
2. 你先用 2 到 3 分钟回答。
3. 复盘时按“结构、技术深度、指标、取舍、代码锚点、诚实边界”六项打分。
4. 再回答追问。

重要性定义：

| 优先级 | 含义 |
|---|---|
| P0 | 高频且简历强相关，答不好会直接影响项目可信度。 |
| P1 | 大厂常问，能体现工程深度和可落地能力。 |
| P2 | 加分题，主要用于拉开和普通 Agent/RAG 项目的差距。 |
| P3 | 低频拓展题，用于准备算法岗、Infra 岗或压力追问。 |

回答结构建议：

```text
背景 -> 目标 -> 架构/流程 -> 我负责的部分 -> 难点与取舍 -> 指标/验证 -> 后续优化
```

## 模块二：Agent 架构与工作流编排

### Q7. 为什么 CoursePilot 要设计 Router、Tutor、QuizMaster、Grader 多 Agent，而不是一个 Agent 加多个 prompt？

为什么问：Agent 面经高频问多 Agent 怎么编排。你的简历明确写了 Router+Tutor+Quiz+Grader，必须说明职责边界和复杂度代价。

重要性：P0

追问：

- Router 输出什么决策？
- Tutor、QuizMaster、Grader 的输入输出有什么不同？
- 多 Agent 带来的延迟和维护成本怎么控制？

### Q8. 你的多 Agent 是“中心编排”还是“Agent-to-Agent 自由对话”？为什么这样选？

为什么问：大厂会追问 Agent 系统是否可控。课程学习场景涉及出题、评卷、记忆写入，中心编排更利于约束和回归。

重要性：P1

追问：

- 中心编排会不会降低 Agent 自主性？
- 哪些状态由 Runner 管，哪些由 Agent 自己决定？
- 如果未来加一个 StudyPlanner Agent，怎么接入？

### Q9. Router 的 Plan 和 Replan 机制怎么设计？什么时候允许重试，什么时候不能重试？

为什么问：腾讯面经问 Agent 失败/中断如何处理和重试安全。你的代码里有检索为空、工具失败、回答质量偏低等 replan 原因，也有副作用分支不重试。

重要性：P0

追问：

- 为什么有写文件或写记忆副作用时不应该自动 replan？
- 流式输出场景为什么不能随便重跑？
- 如何避免重试导致重复扣费、重复写入或重复调用工具？

### Q10. 练习模式里，系统怎么判断用户是在“请求出题”还是“提交答案”？误判会有什么后果？

为什么问：你的简历写了学习-练习-考试闭环，面试官会从状态机角度追问。这个问题能看出你是否真正理解 Grader 路由和 quiz_meta/exam_meta。

重要性：P1

追问：

- 如果用户回答得很短，比如“选 A”，系统怎么定位原题？
- 多轮历史被裁剪后，题目元数据还安全吗？
- 误把出题请求当成答案提交，会怎么兜底？

### Q11. Dify 项目里的“状态化经历收集”是怎么做的？为什么需要 flag + XSID + SQL 回写闭环？

为什么问：这段是你第二个项目最像真实业务难点的部分。面试官会关心你如何防止复杂履历录入中的误删误改。

重要性：P0

追问：

- 新增、修改、删除为什么要抽象成统一结构化判定？
- 字段补全和完整度校验放在哪个节点？
- 如果用户半路退出，状态如何恢复？

### Q12. 如果让你设计一个金融转账场景的 Agent，工具超时或失败时怎么保证资金安全？

为什么问：腾讯相关面经出现跨境汇款场景的 Agent 超时/失败追问。它会考察你能否把学习系统经验迁移到高风险业务。

重要性：P1

追问：

- 哪些工具调用必须加人工确认？
- 哪些步骤必须幂等？
- 失败后是重试、补偿、冻结还是回滚？

### Q13. LangChain、LangGraph、Dify、Coze 和自研 Runner 的区别是什么？你分别适合在什么场景使用？

为什么问：字节面经问 LangChain/LangGraph，简历写了 Dify、Coze、LangGraph。面试官会判断你是否只是列名词。

重要性：P1

追问：

- LangGraph 的状态图优势在哪里？

## 当前简历的表达策略

- 主线不要说“我做了 Harness”。简历没写这个词，面试官看到的是 RAG + Memory + MCP + 多 Agent。

- CoursePilot 适合讲技术深度，Dify 就业辅导 Agent 适合讲上线落地和业务闭环。
- 面试时必须承认边界：CoursePilot 当前不是大规模生产系统，真实优势是模块完整、链路可解释、能继续补生产化能力。
- 大厂最怕“只会搭 demo”。每个回答都要落到一个具体工程问题：怎么召回、怎么记忆、怎么失败、怎么评估、怎么上线。

## 回答红线

- 不要把 CoursePilot 说成“完全自主多智能体协作系统”。更准确的说法是“中心编排下的多专职 Agent 流程”。
- 不要把 FAISS 说成完整数据库。它在项目里是向量索引层，引用和元数据由检索链路一起维护。
- 不要把 Memory 说成复杂推荐系统。当前更像 SQLite 情景记忆 + 用户画像弱点追踪。
- 不要把 MCP 说成完整远程 MCP 生态。当前重点是本地 stdio MCP 子集、工具 schema、协议边界和失败返回。
- 不要声称已有大规模生产高并发、分布式索引、在线增量更新，除非你已经补了对应实现和压测结果。
- 不要声称 benchmark 已经证明效果提升，除非有真实运行结果。没有跑的数据统一说“已有评测框架，指标待补充”。
- Dify 项目不要说成自研 Agent 框架。应该说“基于 Dify 搭建并上线的就业辅导工作流/知识库 Agent”。
